# Working in the content studio

- Start with `content/strategy.md`, `content/projects.md`, and the [project content playbook](content/project-content-playbook.md). Market Altraware's software, show a concrete business workflow, use the verified product palette and sector-specific visuals, and carry the approved keyword through copy and exports. The project register is not evidence that every listed feature is deployed; keep editorial status and public release status separate.
- For every draft, identify one audience, one provable claim, one visible artifact and one CTA. Check the exact build or public page before making a new claim. Label demo, illustrative and in-development material on screen as needed. Never infer sales, impact, affiliation or earnings from a screenshot or landing page.
- For timed technical videos, use `.agents/skills/tech-video-motion-graphics/SKILL.md`. For a staged-search opening with real website proof and the female Business host, also use `.agents/skills/altraware-search-reels/SKILL.md`. The [existing IG kit](https://github.com/mwijaydavie/instagram-agent-skill/tree/main/content-kit) owns brand tokens and Instagram copy workflows; use the content here for the bilingual editorial queue, evidence and render handoff.
- The three-account runway (`content/runway/`) uses one engine, `production/runway-engine`, which renders spec JSON to 1080x1920/60 fps MP4, SRT and carousel PNGs. Run `node src/cli.mjs check <spec>` before any render; the checker rejects generic keywords, unsourced numbers, overlapping cues and copy outside the safe area. Text is emitted as vector glyph paths, so do not add `<text>` elements or system fonts to a template.
- For future Reels, follow [creative direction](content/creative-direction.md): keep sector art and original SVGs, vary background/scene framing, use credited footage when it helps, and prefer owner voice or a clean VO handoff. Do not repeat the contour style by default.
- For technical Reels, keep natural Swanglish and standard developer terms. Make a TTS scratch cut for review by default, plus a clean picture master and timed script to replace it with owner VO. Do not imply the reference is the owner’s voice.
- The Drive reference is for analysis only. Keep private media, customer/student/child data, farm identifiers, and large exports outside Git. Only use cleared captures or clearly labelled illustrations with public-safe data.
- Research and prepare drafts; do not post, schedule, change social accounts, share private files or deploy without an explicit user request. Keep a dated link for each externally sourced fact. Leave unknown metrics blank.
